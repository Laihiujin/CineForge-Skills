# Security Policy

## Reporting

Do not open public issues for vulnerabilities, leaked credentials, unsafe automation, or private production data. Use GitHub private vulnerability reporting when available, or contact the maintainer through the profile linked to this repository.

Include the affected path or version, reproduction steps, impact, and a minimal proof of concept. Remove API keys, unreleased media, personal data, and third-party confidential assets.

## Scope

Reports should distinguish repository defects from risks introduced by external models, tools, plugins, or production infrastructure.
